# AI-Galgame 实时开发生产引擎 — 最终方案

> 状态：v1 定稿（2026-08-16）
> 前置文档：见条目「AI-Galgame实时开发生产引擎 待测试」（原始构想）
> 本文档为技术选型 + 架构 + 路线图的最终共识。

## 一、项目定位

打造一套 **与 AI 协作的游戏剧本写作流水线 / 生产管理引擎**。Galgame 是首个落地场景，但核心写作层设计为**通用型**，后续可复用于 RPG、AI 影视、动漫脚本。

一句话：**让 AI 在「上下文极其有限」的前提下，也能写出全局统一、伏笔回收、不跑偏的几十万字剧情。**

## 二、核心设计原则（灵魂）

**叙事状态压缩（Narrative State Diff）**——全系统最关键的一条主线。

- **剧情概要**：概括「这一节发生了什么」，是写作指引（给 AI 写作用）。
- **剧情浓缩**：只记录「哪些事改变了世界状态、会影响后续」，是可丢弃上下文里的**状态差量**（人物关系、物品、旗标、世界观变化、未回收伏笔），无关氛围 / 插科打诨可压缩成一句话甚至忽略。

> 类比：`git diff` / 游戏存档状态。AI 写任何一个小节，只需「当前世界状态快照 + 该小节附近锚点」，不必读几十万字全文。

由此推导出系统主线：

**时间线 + 人物状态 + 未回收伏笔 + 各节点浓缩 = 一个可随时「快照」的叙事世界状态。**

## 三、三大支柱

1. **可视化剧情脚本创作 / 章节管理 / 分支管理**（通用写作层）
2. **ComfyUI 素材创作 + 资产库绑定**（素材需求清单驱动）
3. **在线实时预览 + 调试**（自建轻量运行时）

## 四、权威存储格式（已拍板）

- **Galgame**：结构化 beat 作为权威存储；Markdown 只是「视图」，不作为权威。
- **通用写作**：保留自由 Markdown + 可选模板。

beat 核心字段（对齐 LetsGal 的 `dialogue` block，逐字段印证）：

```
{时间, 场景, 角色, 表情, 对白, 立绘, 头像, CG, 旁白}
```

## 五、数据模型

工程文件采用 **JSON + git 友好** 组织（借鉴 LetsGal 已验证的结构）：

```
project.json          项目元信息（分辨率/章节顺序/按键绑定/扩展）
characters.json       角色 + 表情 + 立绘路径 + 头像裁剪框 + 站位
scenes.json           场景（多层视差图层，每层带 depth）
chapters/*.json       脚本 = fragments → blocks[]，block = {type, props, content}
foreshadows.json      伏笔-回收登记表
timeline.json         时间线
variables.json        游戏变量 / 旗标
assets.json           资产库 + 引用计数
```

block 类型（MVP 子集）：`dialogue` / `narration` / `scene` / `character(立绘表情)` / `bgm` / `sfx` / `choice(分支)` / `jump` / `curtain` / `end`。

## 六、系统模块

1. **时间线系统**：每章/节带时间戳，防止剧情错乱；拖动重排后重算时间线。
2. **人物设定系统**：基础人设 + 随时间线/路线更新的「状态补充系统」（关系、性格随事件变化）。
3. **剧情路线系统**：主线/支线、入线条件、分支结局（各自适配不同设定/世界观）。
4. **章节管理系统**：卡片式/积木式，带接线条件，可前后拖动衔接；支持先写高潮再回填铺垫。
5. **伏笔-回收系统**：伏笔登记 → 状态跟踪（未回收/已回收）→ 回收后并入人物/世界状态；用于一致性检查。
6. **浓缩/标签/检索系统**：每节生成浓缩 + 标签；快速回顾关键点，为 AI 提供压缩上下文。
7. **锚点式 AI 协作**：关键剧情点设「锚点」（固定内容，AI 不得改），AI 基于概要 + 锚点衔接细化。
8. **资产系统**：图片绑定到角色立绘/头像/场景/UI；引用计数；空引用 = 待创作清单；支持深度复制。
9. **实时预览调试**：点击任意脚本位置播放；改表情/换场景/插音效/BGM。

## 七、技术栈（已拍板）

对 LetsGal（`@avgplus/engine` v1.5.0，MIT）实测技术栈的借鉴与取舍：

| 层 | 选型 |
|---|---|
| 语言 | TypeScript（编辑器+运行时）+ Python（项目服务） |
| 编辑器 UI | React 18 + zustand + React Flow（分支/时间线图）+ dnd-kit（卡片拖拽） |
| 游戏运行时 | Pixi.js 7 + pixi-filters + howler（音频）+ tween.js |
| 桌面打包 | Electron + electron-builder（另支持 web 导出） |
| 项目服务 / AI API | FastAPI + SQLite（本地 HTTP，复用 MemoVault 模式） |
| 权威存储 | JSON 工程文件（git 友好） |

**决策依据**：LetsGal = Electron + React（编辑器）+ Pixi.js（渲染）+ TS 扩展 SDK + JSON 工程 + electron-builder，经实战验证，且精确命中我们三个诉求（可视化脚本 / gal 预览动画 / 打包发布）。

## 八、战略决策：方向 A（自建轻量运行时）

- 只做高层 beat 直解释：对白/旁白/场景/立绘/表情/分支/BGM，**不做**粒子/相机后期/LUT/振屏等演出特效（P2 再增量）。
- 理由：核心价值（AI 协作 + 叙事状态压缩）是 LetsGal 没有的护城河；运行时只做够用的薄层。
- 后期可加「导出 LetsGal 工程」作为可选功能，不冲突。

## 九、分期路线图

- **P0（纵向切片，最小完整）**：结构化 beat 模型 + 章节/时间线/人物/伏笔 + 锚点 + 浓缩 + 本地 AI API + 最简对话播放器。**目标：证明「状态压缩 + 锚点约束」能写出不跑偏的一小段。**
- **P1**：资产库（图片绑定/引用计数/空素材清单/深度复制）+ ComfyUI 接入 + 批量按脚本生成素材。
- **P2**：完整预览/调试运行时（点击播放/改表情/换场景/插音效/转场），对齐 LetsGal 体验但脚本化。
- **P3**：路线分支图、打包发布、UI 定制。

## 十、测试故事

用一个 **15 分钟玩完的小 demo**：2 个角色、1 条主线、1 个伏笔、约 10 个小节。完整跑通：

大纲 → 章节卡片/时间线 → 人物 → 伏笔 → AI 写几节（带锚点）→ 生成浓缩 → 简单预览 → 资产需求清单。

## 十一、AI 协作 API（草案）

本地 FastAPI 暴露，外部 agent（如 DSH）调用：

```
GET  /api/projects/{id}/context     取世界状态快照（浓缩上下文）
POST /api/projects/{id}/beats       提交/改写小节（带锚点约束）
POST /api/projects/{id}/condense    生成剧情浓缩
POST /api/projects/{id}/foreshadow  登记/回收伏笔
POST /api/projects/{id}/check       一致性检查（设定冲突/伏笔未回收）
```

## 十二、风险与边界

1. **范围失控**是最大风险 → 用 P0 纵向切片强制收敛。
2. 数据模型是成败关键 → 结构化文档 + 关系图混合，起步 SQLite + 邻接表，先不上图数据库。
3. 运行时是「苦活」非「难活」，严格限定 MVP 子集，演出特效后置。

## 十三、编辑器 UI 结构（补充共识）

1. **资产库与脚本编辑器分开页面**：协作写脚本时不看资产库；管理资产库时不看脚本。两套独立视图，互不干扰。
2. **剧情脚本层级**（权威存储已按此建模）：
   - 项目 → 大章节（如「序章」，可自定义概要）→ 子章节（如「000 突如其来的夏日」）→ 小节（对应一个时间段，含剧情概要/浓缩/标签/伏笔/锚点/beat）。
   - 核心编辑单元是「小节」；AI 协作基于小节概要 + 锚点操作。
3. **总览界面**：可展开/折叠大章节，大章节下看到对应子章节；章节可拖动排序，时间线在侧边。
4. **编辑交互**：单击子章节进入弹窗/页面，标题为子章节名；子章节下可新建多个小节；每个小节可编辑概要/浓缩/标签/beat，完成后保存。
5. **章节操作**：编辑、保存、复制、自动实例化资产素材（后续实现）。
